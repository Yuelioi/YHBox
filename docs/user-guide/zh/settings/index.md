# 设置

![Yotta 设置页面](../../assets/settings.png)

Yotta 设置会自动保存到当前电脑。设置中的程序路径、窗口匹配、设备地址、网络地址和凭据不会自动进入可分享
的工作流；工作流只通过稳定槽位引用它们。

## 设置分类总览

| 分类 | 主要内容 | 什么时候需要配置 |
| --- | --- | --- |
| 通用 | 语言、启动行为、截屏方式和日志 | 第一次启动或排查运行问题 |
| 快捷键 | 全局、录制、编辑器和工作流快捷键 | 需要键盘快速操作或发生冲突时 |
| 输入与校准 | 录制鼠标模式、360° 校准档 | 录制或回放相对鼠标轨迹前 |
| 悬浮启动器 | 工作流条目、显示方式和 1–9 快捷键 | 需要在目标程序前台执行高频操作时 |
| AI 连接 | 模型、接口、密钥、能力和提案模型 | 使用 AI 节点或 AI 工作流提案前 |
| MCP | 本机 MCP 服务、端口和连接地址 | 让 Codex、Claude 等客户端操作 Yotta 时 |
| 桌面应用 | 可执行文件与启动参数 | 使用启动/终止应用或 Windows 自动化前 |
| 自动化目标 | Windows、Android、浏览器目标 | 节点需要操作外部程序或设备时 |
| 网络目标 | HTTP 基础地址、超时和响应上限 | 使用 HTTP GET 节点前 |

## 通用

### 语言

切换后主界面会立即更新；部分模板和配置文本在重启 Yotta 后更新。

### 启动与关闭

- “开机自启”在登录 Windows 后启动 Yotta。
- “关闭最小化到托盘”开启时，关闭主窗口不会退出后台运行。
- 真正退出前，Yotta 会显示关闭阶段并释放 Run、快捷键和辅助窗口。

### 截屏方式

- **Auto**：按当前 Windows 环境选择截图实现，适合大多数用户。
- **GDI**：兼容性较好，但部分 3D 程序在后台可能返回冻结画面。
- **WGC**：现代 Windows 图形捕获，后台截图通常更稳定。
- **Mock**：开发调试使用本地 PNG 序列，不用于正常自动化。

修改截屏方式后需要重启。检测标注图仅用于排查识别问题，会写入本机调试目录。

### 日志

可以启用或关闭运行日志、选择最低级别，并决定是否实时显示在底部日志面板。日志用于补充诊断，不代替 Run
时间线中的节点结果和错误码。

## 快捷键

快捷键页只展示已经注册或可配置的条目。点击输入框后按下组合键即可修改，清空输入表示解除绑定。

常见分组包括：

- 系统：强停、校准、窗口捕获等全局操作。
- 录制：开始、暂停、停止或取消输入录制。
- 工作流：直接启动或停止指定工作流。
- 计划：手动触发计划。
- 编辑器：只在工作流编辑器中生效。

如果组合键被系统、编辑器或另一个条目占用，Yotta 会显示冲突来源。捕获新组合键期间，已有全局热键会
临时暂停，完成后自动恢复。

## 输入与校准

### 录制鼠标模式

- 相对模式适合游戏视角和 RawDelta 输入。
- 绝对模式适合桌面 UI、按钮和固定窗口坐标。

修改模式后从下一次录制开始生效。

### 鼠标校准档

360° counts 同时受鼠标硬件 DPI 和游戏内灵敏度影响。不同游戏或不同灵敏度应分别建立校准档，并选择当前
默认档。精准相对录制没有有效校准时会被阻止，而不是使用未经确认的缩放值。

## 悬浮启动器

启动器设置用于添加工作流、文字标题和分隔符，并通过拖拽排序。显示方式、五档尺寸和前九个槽位快捷键详见
[悬浮启动器](../launcher/index.md)。

“启用启动器快捷键”只控制启动器显示期间的 `1–9` 槽位快捷键；它不是“打开启动器”的全局快捷键。

## AI 连接

### 安装模型

每个模型使用稳定安装槽位。需要填写接口协议、精确模型名、API 基础地址和模型声明能力；非 Codex 订阅模型
还需要保存 API 密钥。

远程 API 必须使用 HTTPS。本机 HTTP 只允许回环地址，并需要显式确认风险。保存的密钥不会再次明文显示。

### Codex 订阅

Codex 模型使用本机 Codex 登录，通过 app-server 调用 ChatGPT 订阅。Yotta 不读取或保存 Codex 登录令牌；使用
前先在终端完成 Codex 登录。

### AI 提案模型

从已安装且支持工具调用的模型中选择默认提案模型。单轮步骤上限范围为 8–64，它是防止工具循环的限制，
不是 ChatGPT 订阅或 API 余额。

## MCP

启用后，本机 Streamable HTTP MCP 服务立即启动，无需重启。复制连接地址到兼容客户端即可使用 Yotta 提供的
工作流工具。

监听端口只能在 MCP 关闭时修改。如果自动添加 Codex 配置失败，可以复制连接地址后手动配置。

## 桌面应用

桌面应用保存显示名称、稳定槽位、可执行文件和启动参数。启动参数每行填写一项。槽位保存后不可修改，因为
工作流会通过它引用应用；需要替换程序路径时可以保留槽位并重新选择文件。

删除应用会同时影响引用该应用的自动化目标和工作流，确认前应先检查依赖关系。

## 自动化目标

### Windows 目标

Windows 目标依赖一个桌面应用配置，并使用窗口标题、窗口类和多窗口选择策略定位窗口。固定标题使用精确
匹配，动态标题使用 RE2 正则。标题和窗口类同时填写时必须全部匹配。

输入后端和截图后端决定节点如何操作该窗口。保存前使用“检查当前窗口匹配”确认配置。完整流程见
[自动化目标](../automation/index.md)。

### Android 目标

选择已授权的 ADB 设备和精确应用包名。没有发现设备时，确认模拟器或设备已启动，并允许 USB 调试授权。

### 浏览器目标

填写 CDP endpoint，发现并选择页面。运行时会使用页面 ID 重新发现连接地址；页面被关闭或浏览器调试端口
变化后，需要重新检查目标。

## 网络目标

HTTP 目标保存稳定槽位、基础 URL、最大响应字节数和超时。基础 URL 可以指向本机、私网或远程 HTTP/HTTPS
地址；请只配置你信任的服务。

工作流通过槽位使用目标。响应超过字节上限或等待超过超时时间时，请求会失败并进入节点声明的错误路径。

## 设置保存失败怎么办

设置页会显示当前保存状态。失败时，本次输入仍保留，不要反复切换页面。根据错误提示修正字段或检查磁盘
状态后重试。

如果提示“设置已保存，但运行中的功能未能同步”，不要重复保存；重启 Yotta 让运行态重新加载设置。
