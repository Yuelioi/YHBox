# 计划

计划是当前电脑上的触发配置，可以按顺序提交一个或多个工作流。它适合每日任务、周期检查、固定快捷键入口
和需要统一启动多个流程的场景。

## 创建计划

1. 打开“计划”，新建计划并填写名称。
2. 添加一个或多个目标工作流。
3. 选择触发方式。
4. 设置相邻工作流的启动间隔、启动超时和失败策略。
5. 保存并启用计划。

计划只提交工作流启动请求，不会等待前一个 Run 完成后再启动下一个。需要严格串行完成时，应把步骤组合进
同一个工作流，或由前一个流程显式触发后续逻辑。

## 触发方式

| 方式 | 行为 | 适用场景 |
| --- | --- | --- |
| 手动 | 只在点击运行时触发 | 测试或不固定时间的批处理 |
| 每日 | 按本机时间每天在 `HH:MM` 触发 | 每日签到、固定维护 |
| 间隔 | 每 N 分钟触发 | 周期检查和刷新 |
| 快捷键 | 注册全局组合键 | 不打开计划页快速执行 |
| 一次 | 调度器注册该计划时触发一次 | 临时启动任务，谨慎使用 |

“一次”当前按调度器注册行为工作；应用启动或调度器全量刷新都可能重新注册并再次触发。要求严格只执行一次
的任务，应在工作流内增加自己的持久完成条件，而不是只依赖该触发方式。

## 多工作流与失败策略

- 启动间隔控制相邻工作流提交请求之间的等待时间。
- 启动超时只限制“能否成功进入运行队列”，不监控整个 Run 的完成时间。
- `stop` 在某个工作流无法启动时停止提交后续目标。
- `continue` 记录失败后继续提交剩余目标。

工作流成功入队后发生的节点失败不会反向改变计划已经完成的启动结果，应从 Run 时间线查看。

## 快捷键冲突

计划快捷键和系统、录制、工作流快捷键共享冲突检测。注册失败时，计划仍然保存，但快捷键不会生效。前往
[快捷键](../shortcuts/index.md)查看冲突来源并更换组合。

## 什么时候不用计划

- 需要等待前一个 Run 完成：放进一个工作流。
- 需要启动器显示期间的 `1–9` 快捷键：使用悬浮启动器。
- 只想随时运行一个工作流：为工作流设置全局快捷键。
