# 工作流管理与分享

![工作流列表](../../assets/workflows.png)

工作流列表是创建和维护流程的入口。名称用于日常识别，分类和标签用于筛选，工作流 ID 则是本机引用和问题
排查中的稳定身份。

## 整理工作流

- 名称说明“这个流程做什么”，避免使用“测试 1”“新流程”等长期无法区分的标题。
- 描述记录适用目标、必要前置条件和停止方式，不重复名称。
- 分类用于较大的用途分组，例如游戏、办公或维护。
- 标签用于交叉筛选，例如录制、快捷键、每日任务或特定目标。

批量修改分类和标签时，只会改变明确选择的字段，其他元数据保持不变。

## 复制

复制适合从稳定流程创建实验版本。复制后会得到独立工作流身份，后续修改不会影响原流程。需要复用一段内部
逻辑时，优先使用子图；不要为了少量节点把整个工作流复制成多个难以同步的版本。

## 导出

工作流包包含可移植 Source 和它实际引用的可移植资源，不包含：

- 本机程序绝对路径；
- 当前窗口句柄或浏览器会话；
- Android 当前连接；
- API key 和登录凭据；
- 正在运行的 Run 状态。

导出前先保存并执行一次“检查”。如果工作流依赖本机目标，在描述中注明接收者需要配置的逻辑槽位。

## 导入

1. 在工作流页选择导入。
2. 先查看包信息和工作流名称。
3. 选择创建副本，或在明确知道目标身份时替换现有工作流。
4. 打开导入结果并执行“检查”。
5. 在当前电脑重新绑定应用、自动化、网络和 AI 槽位。

创建副本最安全，不会覆盖本机已有工作流。替换操作会检查目标修订号和 Source hash；本机内容已经变化时，
系统会拒绝覆盖而不是静默采用最后写入者。

## 分享给其他人

接收者导入后，需要按自己的电脑重新配置目标。工作流引用的是逻辑槽位，不应该要求对方拥有与你完全相同
的安装路径或窗口身份。

输入录制可以随工作流资源一起携带，但相对鼠标轨迹的校准仍是本机设置。分享精准轨迹时，应说明适用游戏、
游戏内灵敏度和录制分辨率。

## 删除

删除前，Yotta 会检查启动器等本机配置是否仍引用该工作流。存在引用时先移除引用，再删除工作流。删除不会
停止已经创建的独立 Run；如有运行中的实例，先从工作流入口或时间线停止。
