# 流程控制节点

## Run 开始

每次 Run 开始时发出一次信号。主图通常保留一个明确入口，并从这里连接第一项操作。

## 延迟

等待指定时长后继续。延迟适合节流、动画等待或两次操作间隔；如果后续动作依赖画面或窗口状态，优先使用
能检测该状态的节点，而不是猜一个固定时间。

## 分支

根据布尔条件选择路径。条件为 true 和 false 的两个出口只会触发其中一个。复杂判断可以先用比较、文本或
判断节点产生布尔值，再连接到分支。

## 循环

循环节点运行有界次数，并在每轮循环体完成后进入下一轮。它适合轮询页面、重复操作列表或定期检测状态。

循环中应至少包含一种退出或等待机制：

- 满足条件后走“中断”；
- 不满足时延迟后进入下一轮；
- 为等待、网络请求等节点设置超时；
- 使用合理的最大次数，避免无法停止的高频循环。

需要长期监测时，也应让每次检查之间存在延迟。无限循环仍可以由 Run 停止操作或全局强停快捷键取消。

## 结束分支与抛出错误

“结束分支”表示当前路径正常结束，不再发出信号。“抛出错误”表示业务失败，并把稳定错误码写入 Run 证据。
二者不要混用：未命中可选条件通常是正常分支结束，关键前置条件缺失才应作为错误。
