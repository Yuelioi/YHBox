# 流程与状态节点

这组节点决定工作流何时开始、下一步执行什么、是否重复，以及如何在一次 Run 内保存状态。

## 事件

| 常用节点 | 用途 | 常见场景 |
| --- | --- | --- |
| Run 开始 | 每次 Run 发出一次入口信号 | 所有主图的默认入口 |

## 流程控制

| 常用节点 | 用途 | 注意点 |
| --- | --- | --- |
| 分支 | 根据布尔条件选择 true/false 路径 | 判断逻辑应放在上游数据节点 |
| 延迟 | 等待指定时长后继续 | 不要用它代替可以检测的状态 |
| 重复 | 重复执行一段流程 | 配置退出条件、间隔和合理上限 |
| 遍历 | 对列表中的每一项执行循环体 | 循环体完成后才处理下一项 |
| 重试区域 | 在失败后重新执行受控区域 | 只重试瞬时失败，不重试配置错误 |
| 强类型 Switch | 根据一个值选择多个 case | case 多时比连续嵌套分支清楚 |
| 结束分支 | 正常停止当前路径 | 不记录为失败 |
| 令工作流失败 | 用稳定错误码终止路径 | 用于关键业务条件不成立 |

循环、遍历和重试都拥有自己的执行区域。“继续”或“中断”只影响所属区域，不会跳出任意外层流程。复杂用法见
[定期检查条件](scenarios.md#场景一每隔一段时间检查条件)。

## 状态

| 常用节点 | 用途 | 常见场景 |
| --- | --- | --- |
| 读取状态 | 读取当前 Run 中的状态值 | 计数器、开关、最近一次结果 |
| 写入状态 | 保存或覆盖状态值 | 在不同分支间共享数据 |
| 增加状态 | 原子增加整数或数字状态 | 循环次数、成功次数 |
| 状态元数据 | 查看状态类型和版本信息 | 调试状态绑定 |
| 状态最后变化 | 获取状态最后修改证据 | 判断是否需要再次处理 |

状态属于当前 Run，不是跨程序启动的永久配置。需要长期保存的数据应写入明确的文件、网络服务或其他持久目标。

## 时间与随机

| 常用节点 | 用途 |
| --- | --- |
| 观察时间 | 取得当前运行观察到的时间 |
| 启动秒表 / 读取秒表 / 停止秒表 | 测量流程区间耗时 |
| 随机整数 / 随机数 / 随机布尔 | 生成记录在 Run 中的随机结果 |
| 随机选择 | 从列表中选择一项 |

随机和时间观察结果会进入 Run 证据，重放和调试时不会把它们伪装成确定性计算。
