# 节点入门

节点是工作流中的最小操作单元。每个节点都有固定版本的契约，声明输入、输出、配置字段、可能的错误和运行
状态。编辑器只允许连接类型兼容的端口。

## 节点分类

当前 Catalog 按职责区分事件、流程控制、状态、时间、随机、逻辑、比较、数学、文本、集合、JSON、类型转换、
坐标、自动化、应用、文件与日志、网络、脚本、AI 等分类。用户指南按任务把它们组织成四个分册：

| 分册 | 包含的 Catalog 分类 | 常见用途 |
| --- | --- | --- |
| [流程与状态](control-and-state.md) | event、control、state、time、random | 入口、分支、循环、重试、状态和计时 |
| [数据处理](data-processing.md) | logic、comparison、math、text、collection、json、conversion、geometry、data | 判断、计算、文本、列表、JSON 和坐标 |
| [自动化与输入](automation-and-input.md) | automation、application | 窗口、键鼠、应用和输入录制回放 |
| [文件、网络、脚本与 AI](integration.md) | io、network、script、ai | 文件读写、HTTP、日志、脚本和模型调用 |

复杂组合见[节点使用场景](scenarios.md)。[流程控制节点](control-flow.md)和[输入节点](input.md)提供更深入的
专题说明。

## 如何选择节点

先从任务结果倒推：要重复执行一组动作，可以播放宏或精准录制；要定期检查条件，则在外层增加循环和延迟；
要根据结果选择不同路径，则使用分支。

## 端口语义

- 信号输入/输出：控制执行顺序。
- 数据输入/输出：传递值，不单独触发节点。
- 错误输出：节点声明的可处理失败，例如目标不可用或请求超时。
- 状态输出：表达正常但未满足条件的结果，例如等待耗尽。

如果某个失败属于流程预期，应连接节点的错误或状态路径处理；如果属于配置、存储或运行环境问题，Yotta 会
显示应用级错误，并提供操作 ID 用于关联日志。

## 配置值与连接值

输入既可以直接填写固定值，也可以连接上游输出。固定值适合不变参数；连接值适合运行时计算结果。使用目标
槽位、资源或工作流引用时，应通过选择器选取，避免手工复制内部 ID。

## 节点升级

打开旧工作流时，Yotta 会尝试升级兼容节点。无法安全升级的节点不会被静默删除；检查或保存会指出具体节点
和字段。遇到这种情况，应替换节点并重新确认连线。
