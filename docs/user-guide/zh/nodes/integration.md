# 文件、网络、脚本与 AI 节点

这组节点会访问本机文件或已配置的外部能力。目标配置本身就是授权；只连接你信任的路径、服务和模型。

## 文件与日志

| 常用节点 | 用途 |
| --- | --- |
| 读取文本 | 从允许的文件输入读取文本 |
| 读取 JSON | 读取并解析 JSON 文件 |
| 读取图像 | 把图像文件变成可传递的图像值 |
| 保存图像 | 把图像写到明确目标 |
| 文件信息 | 读取文件大小、时间等元数据 |
| 写入日志 | 把诊断信息写入 Run 日志 |

日志节点适合记录关键状态和有限摘要，不要在高频循环中写入大量重复内容。

## 网络

| 常用节点 | 用途 |
| --- | --- |
| HTTP GET | 从设置中选定的 HTTP 目标读取数据 |

HTTP 目标配置基础地址、超时和响应字节上限。节点只填写相对请求信息。把返回文本连接到“解析 JSON”，再用
“JSON 路径”读取字段，是常见的数据获取流程。

```text
Run 开始 → HTTP GET → 解析 JSON → JSON 路径 → 比较 → 分支
```

超时、响应过大和服务端失败应分别处理；不要对认证或配置错误无限重试。

## 脚本

| 常用节点 | 用途 |
| --- | --- |
| 执行脚本 | 在隔离的脚本 worker 中运行受支持脚本 |

脚本适合表达节点组合难以清楚描述的小型计算，不应绕过已有目标、文件、网络或输入边界。对外部输入做类型和
长度检查，并为脚本设置合理时限。

## AI

| 常用节点 | 用途 |
| --- | --- |
| 生成文本 | 根据 prompt 生成文本结果 |
| 提取结构化数据 | 按声明字段生成 JSON 结果 |

AI 节点使用“设置 → AI”中安装的模型槽位和凭据。结构化提取应声明稳定、有限的字段；如果只是生成自然语言，
使用生成文本节点更直接。

模型输出不是可信指令。把结果传给应用、网络或自动化节点前，应通过比较、结构化字段或人工确认限制执行范围。
