# Run 与调试

每次启动工作流都会创建一个独立 Run。Run 固定使用启动瞬间保存的工作流版本和目标配置快照；之后继续编辑
只影响下一次运行。

## 运行状态

| 状态 | 含义 |
| --- | --- |
| 排队中 | Run 已保存，等待执行器接收 |
| 运行中 | 正在执行节点或等待外部操作 |
| 成功 | 所有活动路径正常结束 |
| 失败 | 出现未处理错误或显式失败 |
| 已取消 | 用户或调用方请求停止 |
| 已中断 | 上次程序退出时 Run 尚未正常结束 |

Yotta 启动后不会自动重放中断的工作，以免重复点击、输入或网络操作。

## 时间线

时间线按顺序展示：

- 节点开始、成功、失败、取消或错误路由；
- 节点调用的外部动作及结果；
- 等待、进度和连接状态；
- 失败节点、尝试次数和稳定错误码。

排查问题时先找到第一个失败节点，再看其输入、动作和错误码。后续失败往往只是前一个条件没有满足的结果。

时间线可以分页查看和导出 JSON。导出文件适合提交问题时附带，但分享前仍应检查是否包含业务数据或本机路径。

## 停止 Run

- 工作流列表或编辑器中的运行入口在对应 Run 活跃时可再次触发停止。
- 悬浮启动器中的运行条目会变成停止入口。
- 全局强停可以停止所有活动 Run。

取消会传播到延迟、循环、输入播放、脚本和适配器。运行时还会释放按住的键盘或鼠标输入租约。

## 断点调试

调试 Run 使用和普通运行相同的节点与目标，不是无副作用模拟器。断点会在指定节点前暂停，你可以：

- 查看当前图路径、节点和尝试次数；
- 检查输入、状态和已产生的值；
- 继续运行；
- 暂停正在运行的调试 Run；
- 单步执行下一节点。

涉及真实窗口、键鼠、文件或网络的节点，在调试中仍会产生真实副作用。调试前使用测试目标或可恢复数据。

## 常见判断

- 没有创建 Run：通常是工作流检查、目标或凭据准入失败。
- 已创建但一直排队：检查运行时是否正在关闭或执行器是否可用。
- 节点进入错误出口：这是工作流声明的可处理失败，应检查连接的错误路径。
- Run 直接失败：查看第一个未路由错误和操作 ID。
