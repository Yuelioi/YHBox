# ⚠ 视觉伺服(颜色检测+屏幕X转向)是2D思路,别硬塞3D场景导航

SUMMARY: 颜色检测+屏幕X偏移转视角是2D屏幕自动化思路, 在3D场景导航/锁定里结构性不收敛
READ WHEN: 想用 颜色检测/找图 + 按屏幕偏移转视角 做 3D 场景的转向/锁定/导航前; 设计'让框架在 3D 游戏里走位/面向目标'类能力前

---

## 一句话

**别用「颜色检测/找图 取屏幕坐标 + 按屏幕 X 偏移比例转视角」去做 3D 场景的转向/锁定 NPC/导航。** 这是 2D 屏幕自动化的思路,3D 里结构性不收敛。用户原话:"二维场景的节点 非要放三维场景"。

## 背景

为 3D 第三人称游戏(异环)做"收物资→撤离"自动化,设计了 `TurnToTarget` 节点(吃屏幕目标点 Point,按 `dx=(X-0.5)×Gain` 转一步 yaw,Aligned/Turning 双出口,见 [[../landed/plans/2026-06-05-turn-to-target-node]] / 已并入代码),配 `DetectColor`(出 `lastColor.center`)+ `GetSys` 桥接喂目标点,放 `Loop` 里收敛。真机试了多轮,**调不出来**。

## 为什么 3D 里必然崩(逐条)

1. **偏移→角度非线性**:屏幕偏移和需要转的角度是 tan/投影关系;固定 `Gain` 未校准 → 必然过冲(震荡)或爬不动。references(像素 aimbot)都强调**必须先校准灵敏度**才能算位移,我们一路在猜 Gain。
2. **yaw-only 管不了 3D 纵向/纵深 → "跑头顶"**:目标是 3D 点,大幅横扫视角时近处目标在屏幕上走**弧线、还会往上爬**;只转左右永远没法把偏上/偏下的东西居中,硬扫会把它甩到画面顶部甚至身后。用户原话:"转了60度 他可能跑我头顶上了"。
3. **颜色质心不是"锁定"**:`DetectColor` 给的是 ROI 内**所有命中像素的质心**。视角一转,粉/红物体进进出出、固定 UI(队友头像/HUD 红点)也被算进去拖偏质心、NPC 还自己走 → "目标点"一直跳,没有稳定可收敛的东西。
4. **没有 latch + 无校准** 叠加 → 表现就是"一直转"(永不居中)或"完全没反应"(步子被砍到 ~1°/步,肉眼无感)。
5. **更底层:相对鼠标位移不是"确定的角度函数"**(用户最终一刀)。`TurnToTarget` 默认 `dx counts → 固定角度、与光标起点无关`,但用户实测**从光标 (0,920) 转 和 从 (500,920) 转结果不一样** → 异环 里相对位移依赖**起点**(鼠标加速 / 或游戏按绝对光标+边缘 clamp 采样)。起点不定 → 同一 dx 不是确定角度 → 节点"按偏移转固定角度"的核心前提**直接不成立**。注:`pkg/input/input.go MouseMoveRel` 每帧 setCursorPos 把光标钉到客户区中心(本想消除起点影响),但只在拿到 client rect 时生效、且对有鼠标加速/绝对采样的游戏无效——所以"原地转固定角度"在这类游戏不可靠。要可靠转向得先解决"位移→角度"的确定性(校准 + 关游戏内鼠标加速 / 或拿游戏态),不是这个节点能兜的。

## 校准副产物(异环,实测)

纯输入探针(`MouseMoveRel` 原地转,绕开检测)实测:**~2000 mouse counts ≈ 1/3 圈多一点(~130°)→ 异环 Counts360 ≈ 5500(约 15 counts/度)**。`MouseMoveRel` 的 dx 是**原始 counts、不被 Counts360 缩放**(`node_services.go inputAdapter` 直透;Counts360 只用于录制片段跨机回放 + 是 validator 的 `MISSING_MOUSE_CALIBRATION` 强制声明)。

## 结论 / 怎么做

- **3D 场景里要稳的"面向目标/走位",需要游戏态(目标世界坐标 / 小地图),屏幕找色给不了** → 超出本框架范围,别硬做。
- **框架的甜区是"检测 + 按键"**:撬锁提示→按 F、识别回城点/物资高亮→记个变量通知主流程。3D 移动顶多靠**固定关卡的盲走(按住 W X 秒 + 转固定角度)**,且脆(刷怪/位移误差就乱)。
- `TurnToTarget` 当个**2D/UI 场景**的"把某屏幕点转到中心"还行(那才是它的本分);**当 3D 导航/锁人不行**。它的 spec/plan 里"DetectColor.Center 直连 Target"的用法示例还是错的(数据流要走 `GetSys`,见 [[move-delete-update-referrers]] 同级的 [[2026-06-05-node-data-flow]] checklist)。
- 评估"让框架在 3D 游戏里导航/锁定"类需求时,先回到这条:**不是调参问题,是方法和 3D 现实对不上**。
