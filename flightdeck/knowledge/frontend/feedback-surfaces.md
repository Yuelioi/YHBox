# Feedback surfaces

同一个事件只拥有一个主要反馈表面。不要让 modal、页面横幅、inline error 和 toast 同时消费同一异常。

## 选择顺序

- 字段级错误：放在字段旁，保留输入，并说明如何修复。
- 当前区域可恢复的持久错误：用区域内 alert；允许关闭，并在可定位时提供“定位问题”。
- 后台、跨窗口或触发点已经消失的失败：用 toast。
- 页面首次加载失败且无法继续：用页面级 failure state。
- 必须阻止用户继续、且需要明确选择：才用 modal。

## 硬规则

- 用户关闭一种反馈后，不得从另一份状态重新露出同一个错误。
- 错误码只能作为辅助诊断信息，不能单独成为用户文案。
- 持久 alert 已经显示错误时，不再发同内容 toast。
- modal 统一通过 `BaseModal.vue`；业务组件不直接使用 `UModal`。
- 可恢复错误必须保留用户输入或草稿，并给出重试、定位、重新加载等下一步。

编辑器保存失败由 `EditorSession.saveError` 独占；初次打开失败由 `openFailure` 独占。两者不可互相回填。
