# 显示偏好不能充当能力门控

“基础/专业”之类的二元模式容易把用户身份和界面复杂度混在一起。若一个开关同时隐藏变量、调试、输出绑定、节点改名、修复建议和技术元数据，用户必须记住功能属于哪个模式；当快捷键、命令面板或右键菜单仍能绕过隐藏时，这个模式又不再是可靠边界。

显示偏好应只控制信息密度、默认展开状态和低频技术元数据。以下能力必须始终可发现，或在相关上下文出现：

- 完成主要编辑任务所需的输入、输出绑定、变量和命名能力。
- 检查、调试、错误修复建议等故障恢复能力。
- 与当前对象直接相关的面板入口和状态。
- 命令面板、快捷键、右键菜单与可见导航必须遵守同一能力模型。

真正适合收进“简洁/完整”设置的内容包括对象 ID、内部 kind、复制 JSON/脚本信息、节点详细日志开关等低频技术元数据。设置应使用描述界面结果的名称，避免用“基础/专业”给用户分级。

实施或评审显示预设时至少检查：

- 切换前后究竟哪些能力消失，是否包含主任务或恢复链路。
- 可见入口、快捷键、命令面板和上下文菜单是否一致。
- 互斥选择是否使用 select/radio 语义，而不是多个 checkbox。
- 模式切换是否会让远端区域无提示地消失或关闭。
- 简洁视图是否通过上下文披露减噪，而不是靠全局隐藏制造记忆负担。
