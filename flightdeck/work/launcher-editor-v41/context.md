# 快捷入口编排优化上下文

## 产品决定

- 同一工作流允许在启动器中出现多次，以支持不同分组、名称和图标。
- `LauncherBlock.id` 是入口实例身份；`workflowId` 是执行目标身份。hover、焦点、键盘导航、排序和删除不得再用 `workflowId` 充当入口身份。
- 工作流运行状态仍按 `workflowId` 投影；同一工作流的多个入口可以同时显示正在运行。
- 尺寸是启动器级“内容尺寸”，不是单个入口的任意像素值。四个值为 `xsmall`、`small`、`medium`、`large`，缺省归一为 `medium`。
- 设置页不提供模拟实时预览；用户可以打开真实启动器并与设置页并排观察实时变化。
- 添加工作流使用独立搜索选择器，支持名称、描述、ID、分类、标签、分页、批量添加和已添加次数；重复入口不禁用。

## 实现约束

- 延续现有 Nuxt UI、Tabler 图标、dark semantic token 与设置页共享结构。
- 设置写入只经 settings store 串行队列。
- 使用现有 `WorkflowService.QuerySources`，不增加重复后端查询能力。
- 大结果集必须有上限或虚拟化，搜索需要防抖，交互支持键盘和明确焦点。
- 保留当前工作区中与 AI 密钥输入修复有关的未提交改动。
- 开发阶段只跑针对性测试；所有修改完成后只运行一次 `task check`。
