# 资源管理页统一上下文

## 用户目标

- 计划和资源库应与工作流首页使用同一套管理视图与操作语言，而不是各自保留历史页面形态。
- 计划需要完整的名称、描述、分类、标签和日期信息，并支持搜索、筛选、显示列和底部分页。
- 计划名称和启用状态属于基础信息，创建或编辑时必须始终可见，不能藏在高级设置。
- 资源库的“管理”按钮是旧时代入口，应删除；筛选、选择和批量操作直接出现在默认页面。

## 设计基准

- 工作流首页是本轮唯一产品内基准：页面标题区、搜索与筛选、列选择、表格行、选择工具栏和分页沿用
  现有视觉与交互语法。
- 三页保持各领域有意义的列和操作，不为了像素级相同而制造无意义功能。
- 暗色表面继续使用语义 token 和现有层级，不新增裸 zinc/black/white 或装饰性渐变。

## 实现边界

- 计划元数据通过正式 Go 服务合同和 Wails 生成入口更新；不手改 `frontend/bindings/`。
- 资源库沿用现有查询、分类、标签、排序和分页能力，删除仅用于切换管理状态的分支。
- UI 验收使用 CLI Playwright 驱动本地页面并保存截图，不依赖应用内浏览器。
- Tailwind 是业务页面布局与局部视觉的默认实现；根 `style.css` 只承载主题 token、基础样式和确实跨页
  复用的 utility。需要深层 Nuxt UI 选择器或复杂响应式壳层时，CSS 文件放在对应页面旁。
