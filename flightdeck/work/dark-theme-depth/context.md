# 暗色主题层次与设置中心视觉收口上下文

## 用户目标

- Yotta 继续保持 dark-only 桌面工具定位，但不能再“黑洞洞”，需要在长时间操作和高信息密度下仍能
  快速辨认画布、区域、控件、交互状态与浮层。
- 本轮是对现有视觉系统的定向修正，不更换产品功能、信息架构、Nuxt UI 技术栈或 Tabler 图标体系。

## 已确认问题

- 旧规则把 `--ui-bg` 固定在 zinc-950，并要求 raised surface 的卡体仍使用同一个纯黑背景，只用顶部
  高光、内高光和阴影表达浮起；在大面积设置页和管理页中，静止状态缺少稳定明度差，形成“黑洞”观感。
- 阴影在近黑背景中的辨识力有限，不能替代实体表面的明度差；顶光也不能承担页面区域分组。
- 设置页仍须保持有限宽度的连续内容流。允许少量一级实体区块，但不得恢复字段、列表、详情再层层套同色
  卡片的结构。

## 视觉策略

- 模式为 Operate：颜色服务于层级、导航、选择、状态和焦点，不作为大面积装饰。
- 情绪温度为中性偏冷；主画布保持近黑，一级实体表面稳定提亮，hover/selected 再提升一个可辨认层级。
- 全局角色使用语义 token：canvas、sunken、surface、surface-hover、surface-strong、overlay、
  border、text 与 semantic status。组件不散写 zinc/black/white。
- 设置分类强调色只用于图标、活动导航、焦点和极轻的区域导向；不得替代主操作色或状态色，也不得成为
  唯一的信息编码。
- 静态一级区域优先使用实体明度和必要分隔线；阴影保留给真正遮挡内容的 overlay，不用来伪造所有卡片
  的层级。

## 验收边界

- 首轮覆盖设置中心、工作流管理、资产管理以及共享 `AppCard` / `ListRow`；若共享 token 影响其他页面，
  在最终视觉复验中抽查代表性页面。
- 正文、关键控件和焦点指示满足 WCAG AA；颜色之外保留文字、图标、位置或边框等非颜色线索。
- 开发中先跑定向前端测试、类型、i18n 与界面检测；交付前按仓库增量路由运行一次 `task check`，不默认
  运行 `task check:full`。
