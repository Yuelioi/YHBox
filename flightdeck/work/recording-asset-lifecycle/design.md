# Design — 录制资产生命周期

## 1. 功能摘要

为普通用户补齐录制从开始到清理的完整生命周期：录制中可以明确取消；停止后先进入待保存状态，填写名称并可选分类/标签，只有确认后才正式入库；资产库可以一次清理所有未被流程引用的简易录制和精准录制。

专业信息保留但不前置。默认流程只回答三个问题：是否保留这次录制、它叫什么、是否需要清理无用录制。

## 2. 主要用户动作

停止录制后，为有价值的录制起一个能识别的名字并保存；不满意则直接丢弃，不产生库内垃圾。

## 3. 设计方向

遵循 `.impeccable.md` 的“清晰、可靠、高效”：延续现有深色自动化工作台与翠绿主操作色，危险动作使用语义错误色，处理中使用稳定而克制的状态反馈。文案说结果，不暴露 `SubgraphID`、`ClipID`、referrer 等内部术语。

高级字段采用渐进披露：名称是唯一必填项；分类和标签作为次级整理区，保持可见但不与保存动作争夺层级。

## 4. 布局策略

### 录制 HUD

维持紧凑控制条，状态在左，操作在右：

- 录制中：暂停、停止、取消。
- 暂停中：继续、停止、取消。
- 停止是主要动作；取消是明确但不抢眼的危险动作。

取消需要一次轻量确认，说明“本次录制不会保存”；确认后立即结束 hook、关闭 HUD、不创建任何资产。

### 停止后的保存面板

停止不再直接入库，而是回到主编辑器打开单一焦点的“保存录制”面板：

- 顶部说明录制类型和时长/步骤摘要。
- 名称输入自动聚焦且必填，不使用纯日期作为已完成名称。
- 分类、标签位于名称下方，沿用现有可创建选项控件。
- 底部主动作“保存并添加到画布”，次动作“丢弃”。重新录制覆盖节点时，主动作改为“保存并替换”。

### 资产库清理

在录制资产所在的库工具栏提供“清理未使用录制”。扫描后打开结果面板：

- 分开统计简易录制与精准录制。
- 列出将删除的名称，默认全选。
- 明确显示被引用而跳过的数量；这些资产不进入删除集合。
- 确认按钮显示实际删除数，例如“删除 12 个未使用录制”。

个人删除遇到引用时不再给一个无法完成的确认框，而是解释“仍被 3 个流程使用”，提供“查看引用”；不支持静默强删并制造坏引用。

## 5. 关键状态

- 倒计时：可取消倒计时，沿用现有行为。
- 录制中：暂停、停止、取消均可用。
- 暂停中：继续、停止、取消均可用。
- 正在停止：禁用重复操作，显示“正在整理录制…”。
- 待保存：录制数据尚未进入正式资产库。
- 名称为空：保存禁用，并给就地提示。
- 保存中：锁定表单，防重复提交。
- 保存失败：保留待保存数据，可重试或丢弃。
- 丢弃确认：说明不可恢复；成功后不留孤儿资产。
- 清理扫描中：显示进度/加载态。
- 无可清理项：说明“所有录制都正在使用或已整理干净”。
- 有可清理项：展示候选、跳过引用项与预计释放数量。
- 部分删除失败：保留失败列表并允许重试，不把整批假报为成功。

## 6. 交互模型

1. 用户开始录制。
2. 录制中可暂停/继续；选择取消则确认后彻底丢弃本次会话。
3. 选择停止后，后端产生 pending 结果，不注册为正式库资产。
4. 主编辑器收到 pending token，打开保存面板。
5. 用户填写名称，可选分类和标签。
6. 保存时后端原子 finalize：创建 Subgraph 或 Clip、写元数据、返回正式 ID；前端随后添加或替换画布节点并保存容器。
7. 丢弃时后端释放 pending 数据；窗口关闭或超时也不得把 pending 结果暴露到资产库。
8. 清理时后端以当前引用扫描结果为准，只删除 recording-derived 且零引用的 Subgraph/Clip；提交前再次校验引用，避免扫描后到删除前的竞态。

## 7. 内容要求

关键文案：

- “取消录制” / “本次录制不会保存”。
- “保存录制” / “给这次录制起个容易识别的名字”。
- “保存并添加到画布” / “保存并替换”。
- “丢弃录制”。
- “清理未使用录制”。
- “将删除 {n} 个未使用录制；另有 {m} 个仍被流程使用，已跳过”。
- “没有可清理的录制”。

名称允许 1–80 个字符，去除首尾空白；分类为单值，标签为去重多值。所有新增文案必须同步中英文 i18n。

## 9. 开放问题

- 设计无阻塞业务问题。实现时应以 pending token 为边界，避免“先入库、取消后再清理”的假取消语义。
