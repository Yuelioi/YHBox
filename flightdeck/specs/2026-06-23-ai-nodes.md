# AI 节点 — 图里调 LLM (动态带类型 IO + 结构化输出 + vision)

## 0. 定位:这是 "AI 功能" epic 的第②块

| | 子系统 | 方向 | 状态 |
|---|---|---|---|
| ① | 本地 AI 配置(连接 + 双协议 + `llm.Provider`) | 基础设施 | **已落** (`archive/specs/2026-06-23-local-ai-config.md`) |
| ② | **AI 节点(图里调 LLM)** | 我们用 AI | ← 就是这块 |
| ③ | MCP 对外暴露(AI 调我们) | AI 用我们 | 另起 spec(已有 `cmd/yotta-mcp` spike) |

①给了"配好且测得通的连接" + `internal/services/llm` 的 `Provider` 接口(非流式 `Chat` + `ListModels` + `ErrKind` + pooling Transport)。**②把它接进节点系统**:让图作者拖一个 AI 节点、选连接 + 模型、给提示词与任意个带类型输入、拿任意个带类型输出,并能识图。①明确下放给②的(model 选择、动态 IO、结构化输出、vision、Provider 缓存+失效+池调优)在此落地。

> **铁律:破坏性更新,不留兼容。** 项目未发布、无外部用户。删 Screenshot / 改 Image 注册类型 / 扩 `Message` / 改 `applyExecDataEdges` 一律一次切净,不写 shim、不留 deprecated。

## 1. 目标 / 非目标

**目标(In)**
- **AI 节点**:exec 节点,选连接(connectionID,缺省 `ai.default`)+ 模型(combobox,ListModels 建议 + 手填),给 System / User 提示词模板,跑一次非流式 chat。
- **任意个带类型动态输入**:复用现成 `DynamicInputs` / `config.Inputs[]`,提示词用 `{{Name}}` 占位引用;`Image` 类型输入作多模态图像。
- **任意个带类型结构化输出**:用户声明输出字段(名+类型)→ structured output(json_schema / 强制 tool-use / 提示词注入)→ 每字段 = `Done` 出口上一个**可捕获 Data 字段**(逐字段绑变量,镜像 `DynamicInputs`)。**始终**另带 `Text`(模型原文)。
- **vision 识图**:`Image` 成一等流动值;`Capture` 产出图像(可选 PNG/JPEG),**经 exec-data 直连**喂 AI(无需绑变量)。
- **Provider 缓存/失效/池**:按 connectionID 缓存 Provider,取用时按连接指纹自愈;池 per-host 上限/IdleConnTimeout 调优。
- **三个图像节点**:`Capture`(截屏产出 Image)、`SaveImage`(Image→本地文件)、`LoadImage`(本地文件→Image)。Screenshot 拆掉删除。

**非目标(Out)**
- 流式输出;**多轮 agent / 工具循环**(AI 节点是单次调用;tool-use 仅作结构化输出手段,不暴露成能力);**AI 生图**(本 spec"图像生成"=截屏产 Image 值);**嵌套/递归 JSON schema 输出**(先支持标量 + `JSON`(自由对象)+ `List`,深层抽取 YAGNI,`Type` 字段日后可扩);**命名图像引用**(按声明序,用户提示词自述"第一/二张");embeddings/重排/语音;内嵌聊天 UI;③ MCP 执行能力。

## 2. 关键决策

| 决策 | 选择 | 理由 |
|---|---|---|
| 节点形态 | **一个高度可配的 AI 节点** | 用户拍板"AI节点 输入任意个 输出任意个 类型可设";n8n/Dify 范式;一节点覆盖识图/抽取/计算/分类。Inspector 复杂度用折叠面板组织(FE 注记),不拆节点 |
| 输出形态 | **逐字段独立可捕获口**(用户拍板) | 每字段 = `Done` 上一个带类型 Data 字段,逐个绑变量 |
| 输出机制 | **新 `DynamicDataFields` 标志 + `config.Outputs[]`** | **刻意不叫 `DynamicOutputs`**(那是 Switch 出口名动态);本标志是 Data 字段集由 config 声明。**同节点二者并开 → validator 硬错**(强制互斥) |
| 输入形态 | **复用 `DynamicInputs`**(`config.Inputs[]` `{Name,Type,Var?,Scope?}`) | 现成机制;`Image` 也是其中一种类型 |
| 提示词占位 | **`{{Name}}` 双花括号**;字面 `{{` 用 `\{{` 转义 | 提示词常含 `{}` 字面;双括号消歧义。**引用名须在 `config.Inputs[]` 声明,未声明→硬错**(抓拼写) |
| 结构化模式 | **三态 `auto / native / prompt`**(config 存字符串,默认 `auto`) | `auto` Run 时按端点解析:Anthropic→native(tool-use)、OpenAI 官方→native(json_schema)、OpenAI 兼容→prompt(注入)。**模式对所有协议都适用**(Anthropic native=tool-use,prompt=注入);用户可显式锁 native/prompt,切回 `auto` 恢复端点默认 |
| native 不支持 | **新 `ErrKind=unsupported`** | 兼容端点显式选 native 失败 → 明确文案"该端点不支持原生结构化,请切提示词注入",区别于"模型/网络挂了" |
| 结构化解析失败 | **走 `Fail`**;`Fail` 出口 Data 加 **`Text`**(原文) | 节点契约是"产出带类型字段",未达成即失败;**但原文带进 `Fail.Text`**,下游接 Fail 仍能消费模型原文(不只塞 Error)。`ChatStructured` 契约:失败时 `error≠nil` 且 `ChatResponse.Text` 仍填原文 |
| vision 接线 | **exec-data 直连**(`Capture.Image → AI` 数据线 + 紧邻 exec 边),变量+GetVar 作非紧邻退路 | 框架已有 exec-data 同名注入(测试 `TestExecDataEdge_FailCodeIntoDataPin` 钉死) |
| Image 值形态 | **`node.Image{Format,Data []byte}`(编码字节)**,Capture 可选 png/jpeg | 字节直发 base64/写盘/读盘最省转码;**JPEG 选项**(用户提)显著减 vision token + 减 Image 值在节点间流动的内存 |
| Image 注册类型改动 | **改 `types.go` GoType 字符串 + 加 `node.Image`** | grep 证实 `Image` pin 类型**零节点产/消当值**(`*image.RGBA` 全在底层 capture/vision 帧 + 测试,不碰);GoType 仅 FE 元数据;`coerceToType` 无 Image 分支(新增无可迁) |
| Provider 缓存 | **新服务 + `ctx.AI()`**;**取用时指纹自愈** | 指纹 = `hash(Protocol+BaseURL+APIKey)` —— **只 llm 相关字段,排除 Label/ID**(改名不该 evict);变则重建(无事件监听),重建时旧 Provider `Transport.CloseIdleConnections()` 防泄漏 |
| 跨协议 schema 归一 | OpenAI strict(`additionalProperties:false`+全 required)/ Anthropic 强制 `tool_choice` 取首 `tool_use.input`、零 tool_use→Fail / 提示词注入(描述进 System + 容错解析) | 三协议差异在节点层屏蔽;字段类型走统一映射表(§5) |
| 删连接 | **确认弹窗列出引用的 AI 节点**(不静默、不硬拦) | settings 删连接时扫含 `Connection==id` 的 AI 节点,弹窗列节点 ID/label 让用户确认;删后引用节点运行时 Fail(notFound),但用户已知情 |
| 新 Category | **`AI`** + **`Image`** | 需补 `GROUP_MAP` + `nodeGroup.*` i18n(add-node §6) |

## 3. AI 节点形态

**Kind `AI`,Category `AI`,Runnable。`NeedsWindow: false`**(只调 HTTP;截屏在独立 `Capture`)。

**静态输入(`Spec.Inputs`)**

| pin | 类型 | 说明 |
|---|---|---|
| `In` | Exec | 入口 |
| `Connection` | String | connectionID;widget 下拉,FE 从 `settings.ai.connections` 填(显示 Label,值=ID);默认空 = 运行时取 `ai.default` |
| `Model` | String | combobox;FE **按需**拉所选连接的 `ListModels`(开下拉显 loading / 「刷新」按钮显式触发,**非开节点即拉**;会话内按 connectionID 缓存建议;失败可手填;换连接清建议) |
| `System` | String | textarea,系统提示词模板(可空) |
| `User` | String | textarea,用户提示词模板(必填) |
| `Mode` | String | dropdown「自动(按端点)/ 原生 / 提示词注入」结构化模式;config 存 `auto|native|prompt`,默认 `auto`。无结构化输出时无影响 |
| `Temperature` | Number | 可选;空/0 走 Provider 默认 |
| `MaxTokens` | Integer | 可选;Anthropic 侧空则 `llm` 补 1024(①已定) |

**动态输入**:`config.Inputs[]`(`DynamicInputs: true`)。每个 `{Name, Type, Var?, Scope?}`。提示词 `{{Name}}` 插值(渲染时按声明名替换为字符串化值)。**`Image` 类型输入不进文本插值**——改作多模态块(§5);`{{imageInput}}` 渲染成 **`[image]`** 标记(明确"此处为图像、已作附件"),校验另给 warn(§8)。变量直接喂用动态输入的 `Var/Scope`。**输入名与输出字段名是两个独立命名空间**(`{{}}` 只查 `config.Inputs[]`,不碰 `config.Outputs[]`)。

**动态输出**:`config.Outputs[]`(`DynamicDataFields: true`,见 §4)。每个 `{Name, Type}`。

**输出(`Spec.Outputs`)**
- `Done`(Exec),Data = `Text`(String,模型原文,**恒有**)+ `config.Outputs[]` 声明的各字段。
- `Fail`(Exec,`Semantic:"error"`),Data = `Error` + `Code`(`ErrKind`→Code)+ **`Text`(原文,供下游接 Fail 消费)**。

**Run 流程**
1. 解析连接:`Connection` 空 → `ai.default`;查 `settings.ai.connections`;查不到(含 default 不存在/列表空)→ `Fail`,Code=`notFound`,文案区分"未选连接且无默认 / 引用的连接已删"。
2. `provider, err := ctx.AI().Provider(connectionID)`(缓存,§7)。
3. 渲染 System/User(`{{Name}}` 插值,非 Image);收集 `Image` 动态输入 → `[]llm.ImageData`(按声明序)。
4. 解析 `Mode`(`auto`→按端点定 native/prompt);有 `config.Outputs[]` → 构 schema → `provider.ChatStructured(ctx, req, schema, mode)`;否则 `provider.Chat(ctx, req)`。
5. `Set("Text", 原文)`;逐 `config.Outputs[]` 字段 `Set(name, 按类型 coerce)`;`Fire(Done)`。
6. 错误(含结构化解析失败)→ `Fail`,带 `Error`/`Code`/`Text`(原文)。ctx 取消(容器停)→ graceful halt。

## 4. 新框架机制:动态带类型输出 Data 字段(`DynamicDataFields`)

现状:`OutputSpec.Data` 静态;`BindableFields(spec)` 只读静态 `Outputs[].Data`。造一套**与 `DynamicInputs` 对称**的 config 驱动机制。

- **Spec 加标志 `DynamicDataFields bool`**(区别于 `DynamicOutputs`)。**validator 硬错:同节点 `DynamicOutputs && DynamicDataFields`**(语义冲突,强制互斥)。
- **config 形态 `config.Outputs[]` = `[{Name, Type}]`**(PascalCase;Type ∈ 注册表)。后端加 `container.ParseDynamicOutputDecls`(镜像 `ParseDynamicInputDecls`)。
- **可绑字段 config 化**:加 `nodepkg.BindableFieldsForNode(spec, config) []string` = 静态 `BindableFields(spec)` ∪(`DynamicDataFields` 时)`config.Outputs[]` 各 Name,**返回去重(set 合并)**;保留名 `Text` 不进声明(校验层报),`BindableFieldsForNode` 本身只负责合并去重。捕获校验(`validator_capture_refs.go`)与 FE「输出」组改用它。
- **运行时零改**:`applyCaptures` 本就按 `node.config.capture[field]` 写"出口实际带的字段";AI 节点 `Run` 把各声明字段 `.Set()` 即被捕获。`OutBuilder.Set` 不校验字段名。
- **改 config.Outputs[] 的悬空处理**:删/改字段后残留的 `config.capture` 绑定 + 下游 `GetVar` 引用由**现有** `validator_capture_refs.go` 暴露;FE 输出编辑器删字段时**即时扫下游引用弹预警**(与动态输入删除 UX 对齐)。
- **FE**:`adapter.ts` 加 `parseDynamicOutputsCfg`;Inspector 新增「输出口」声明编辑器(镜像 `DynamicInputsEditor.vue`:名字合法/重名/保留名 `Text` 标红);「输出」绑定组按 `config.Outputs[]` 渲染、与静态 `Text` **分组**;AI 节点 Inspector 用**折叠面板**(输入声明 / 输出声明 / 模型参数)控复杂度。

> 通用机制,不写死 AI kind。

## 5. llm 包扩展:结构化输出 + 多模态

```go
type JSONSchema struct { Fields []SchemaField } // {Name, JSONType}
type ImageData struct { Format string; Data []byte } // "png" | "jpeg"
type Message struct { Role Role; Content string; Images []ImageData } // ② 加 Images

type Provider interface {
    Chat(ctx, req ChatRequest) (ChatResponse, error)
    ListModels(ctx) ([]string, error)
    // ChatStructured: mode = "native" | "prompt"。失败时 error≠nil 且 resp.Text 仍填原文(供节点 Fail.Text)。
    ChatStructured(ctx, req ChatRequest, schema JSONSchema, mode string) (resp ChatResponse, fields map[string]any, err error)
}
```

**类型 → JSON 类型 → coerce 映射(单一真相,实现者照表,不自创)**

| 节点 Type | JSON type | 解析回值 coerce | 边界 |
|---|---|---|---|
| `String` | `string` | string 原样 | 非 string → Fail |
| `Number` | `number` | float64 | — |
| `Integer` | `integer` | float64 整值校验 → 取整 | 非整(1.5)/超 int64/科学计数超界/JSON string("123") → **Fail badRequest**;`1.0` 视为整、通过 |
| `Bool` | `boolean` | bool | — |
| `JSON` | `object` | `map[string]any` 原样 | object 自由结构(不深约束,YAGNI) |
| `List` | `array` | `[]any` 原样 | items 不限 |

> **节点类型是 UI 标签**:运行时值就是 Go 的 `float64/string/bool/map[string]any/[]any`(框架既有约定,Inputs coercion 只认 float64/json.Number/string);**无 `node.Number`/`node.Integer` 中间类型**。下游 `coerceToType` 按消费 pin 声明类型再转。文档讲清,避免"Number 是个 Go 类型"的误解。

- **OpenAI native**:`response_format=json_schema`,strict → `additionalProperties:false` + 所有声明字段 `required`;content JSON 串 → parse。
- **Anthropic native**:强制 tool-use —— 定义 tool(`input_schema`=object schema)+ `tool_choice` 钉死。**取首个 `tool_use` block 的 `input`**;**零 tool_use(纯文本/异常)→ error**(节点 Fail,resp.Text=原文);伴随的 text block 忽略。
- **提示词注入(`prompt`)**:schema 描述注入 System(只回 JSON)+ 容错解析(剥 ```` ```json ```` 围栏、trim、取首个完整 JSON 对象);失败 → error(文案只说"模型未返合法 JSON",**不回灌注入的 System 内部**)。
- native 被端点拒(兼容端点显式选 native)→ `ErrKind=unsupported`(文案引导切 prompt)。

**多模态(vision)**
- `Images` 按收集序(= `config.Inputs[]` 声明序),在 user message 里**置于文本 content 之后**(确定顺序)。
- **OpenAI**:user content = 文本块 + 各 `{type:"image_url", image_url:{url:"data:image/<fmt>;base64,..."}}`。
- **Anthropic**:content = 文本块 + 各 `{type:"image", source:{type:"base64", media_type:"image/<fmt>", data:<base64>}}`。
- 节点把 `Image` 动态输入的 `node.Image` 平移成 `llm.ImageData`。

## 6. Image 一等值 + 三个图像节点 + vision 接线

**Image 值形态**:`node.Image{Format string; Data []byte}`(format ∈ png/jpeg)。
- **不可变契约**(类型注释钉死):`// Data is immutable; consumers MUST NOT modify the underlying byte slice.` 值在进程内按引用流动、**不深拷**(内存权衡);误改会跨节点串数据 —— 三节点 + AI 节点均只读,无运行时强制(Go 层不可阻止,文档明确后果)。
- 注册类型 `types.go:93` 的 `Image` GoType `*image.RGBA` → 改 `node.Image`(仅 FE 元数据;**底层 capture/vision 的 `*image.RGBA` 帧代码不动**)。`coerceToType`(`data_pull.go`)加 `Image` 分支。

**三个图像节点(Category `Image`)**

| 节点 | Kind | 输入 | 输出(Done Data) | NeedsWindow |
|---|---|---|---|---|
| 截屏 | `Capture` | `ROI`(Geometry,可选,零值=全帧)、`Format`(String dropdown png/jpeg,默认 png)、`Quality`(Integer 1–100,默认 85,jpeg 生效) | `Image`(node.Image) | **true** |
| 导出到本地 | `SaveImage` | `Image`(必填,data-in)、`PathTemplate`(String) | `Path`(String,绝对路径) | false |
| 从本地加载 | `LoadImage` | `Path`(String) | `Image`(node.Image) | false |

- `Capture`:`ctx.Capture().CaptureROI(roi)` 得 PNG 字节;`Format=jpeg` 则解码 PNG → 编码 JPEG(`Quality`)。**ROI 复用 Screenshot 现有 `Geometry` 输入 + `node.GeometrySchema()`**(现成类型)。转码失败(损坏帧/编码错)→ `Fail`;**双编码(PNG→decode→JPEG)记为已知低效**——`CaptureService` 现仅给 PNG,日后若暴露原始帧再省中转。`Quality` 越界由 §8 校验拦。
- `SaveImage`:吃 `Image` + 模板 → 按 **`Image.Format` 定扩展名(权威,覆盖模板里写错的后缀)** 写盘。**沙箱根 = `<dataDir>/images/`**(新根);复用路径安全检查 + 模板(`checkSafeScreenshotPath`/`expandScreenshotTemplate` 平移,根改 `images/`);模板支持 `{ts}`(ms)/`{date}`/**`{uuid}`**(防并发同毫秒覆盖)。`Fail` 带 `CodeWriteFailed`。
- `LoadImage`:读 `<dataDir>/` 下文件(沙箱:拒绝绝对/`..`/盘符;**比 SaveImage 宽**——可读任意 `<dataDir>` 子目录,**设计意图**:Load 读用户从外部放进 dataDir 任意位置的图,Save 专责截图输出到 images/)→ sniff(仅 **PNG/JPEG**,其他→`Fail` badRequest)→ `node.Image`。**大小上限 10MB**(超→`Fail`;接口契约,非 plan 待定)。

**vision 直连(用户拍板,源码核实)**
- 两条边:`Capture.Done → AI.In`(exec)+ `Capture.Image → AI 的某 Image 动态输入`(数据线)。
- 运行时 `Capture` fire `Done` 携 `Image` → exec token 下发;`applyExecDataEdges` 注入 AI 对应输入。**无变量、无 GetVar**。
- **约束**:`Capture` 须是 AI 紧邻 exec 上游(同 exec 边)。非紧邻/多消费 → 退回绑变量+GetVar。校验器加 **warn**(非硬错):Image 输入接了 exec 出口 Data 字段但源非紧邻上游 → 提示"数据线需配合紧邻 exec 边"。
- **接线细节(已核实)**:数据边 key = `<nodeID>.<pinName>`(`nodeID` = container graph 节点稳定 ID,`data_pull.go buildDataEdgeIndex` 用它;同图两 AI 节点同名动态输入靠 nodeID 区分);动态输入 pin 名 = `config.Inputs[].Name`(`ParseDynamicInputDecls`)。`applyExecDataEdges` 现只遍历静态 `rn.Spec.Inputs` → 改遍历**有效输入列表 = `Spec.Inputs` ∪ `ParseDynamicInputDecls(node)`**,按 Name 注入(ds 解耦建议)。
- **优先级(定死 + 测)**:某动态输入同时有数据线注入与 `Var/Scope` 绑定 → **数据线注入优先**(直连覆盖,无线时回落 Var);沿现有 `pullDataPin` 数据边优先序。
- **加法式安全**:动态输入现在拿不到 exec-data,加注入不破坏现状,连带让 Expr/Script 动态输入也能吃 exec-data(框架行为变化,**plan 须实测 Expr/Script 回归 + 端到端注入**)。

## 7. Provider 缓存 / 失效 / 池(新服务 + `ctx.AI()`)

- 新增 ctx 服务:`AIProviderService { Provider(connectionID string) (llm.Provider, error) }`,挂 `ServiceBundle` + `node.Ctx.AI()`(nullable,测试 stub)。
- 实现(运行时层,能见 `SettingsService`),**单一机制 = 取用时指纹自愈**:
  - 持 `map[connectionID]entry{provider, cfgHash}`。`Provider(id)`:查 settings 得连接 → `cfgHash = hash(Protocol+BaseURL+APIKey)`(**只 llm.New 实际用的字段,排除 Label/ID**)→ 命中且指纹同 → 返缓存;否则 `llm.New` 建新、**旧 entry 的 `Transport.CloseIdleConnections()` 后替换**(防连接泄漏)、存。
  - **失效即自愈**:settings 改了 endpoint/key → 下次取用指纹不符自动重建。无事件监听、无单独 evict。
  - **并发语义(文档化)**:图执行中途改 settings —— 已取用且正在 `Chat` 的用旧连接跑完,下次 `Provider(id)` 才换新。
  - **池调优**:tuned Transport 设 `MaxConnsPerHost`/`MaxIdleConnsPerHost`/`IdleConnTimeout`。
- AI 节点经 `ctx.AI().Provider(id)` 取,不自己 `llm.New`。
- **观测 + 脱敏**:每次调用 log `model / connection Host / latency / ErrKind / 结构化解析成败`;**不打 APIKey**;BaseURL 只打 Host(沿①)。
